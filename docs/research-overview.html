01 / The question

Keep less.
Still know what matters.

“Write a better summary” is too vague. We separate what memory makes possible from what actually helps an agent finish a task.

A.

What does repeated forgetting make impossible?

Imagine saving a small note from a long history. Later, you learn which parts matter—but now you must shrink the note again. Can the first note support every later choice?

Our bit model makes that question exact: fixed memory limits, delayed clues, and no way to reread the discarded source.

B.

What helps a real model recover?

We test prose, structured records, checked receipts and recovery. The latest direction asks whether removing a failed attempt, while keeping its feedback and lesson, helps the next attempt.

The test must beat strong alternatives: directly keep the needed records, retrieve them, or solve again from the released evidence.

01 · ObserveA four-bit source

The initial encoder sees all four values.

02 · CompressKeep two bits

Save a parent memory before relevance is revealed.

03 · UpdateLearn which bit is irrelevant

Reduce to one child bit; discard the parent.

04 · AnswerReceive the final query

Predict one remaining source bit using only the child and public clues.

Timing is the point: the final queried coordinate is revealed after the second memory cut. Bits in this model are not LLM tokens. Model & exact result ↗

Try the small example An illustration of the saved optimal code

Choose four source bits, remove one coordinate, then ask about a remaining coordinate. The final answer repeats the single child bit. This explores an existing mathematical witness; it is not a new model experiment.

The lesson

A good memory is necessary in some tasks, but it is not a guarantee of a good final decision. Direct records, static analysis and indexed recovery must remain in the comparison. A complicated method succeeding alone is not evidence of an advantage.

Evidence boundary: the 810 early record-policy configurations are constructed diagnostics, not 810 independent LLM trials. Historical replay, fake clients and retrospective audits add understanding, not new model samples. Explore offline work ↗

Repeated compression has a real, measurable compatibility cost.

A memory optimized for one stage may not support the best later memory. We established the exact smallest example, extended the theory to joint encoding, and built finite codes under the same declared limits.

The lesson

Theory tells us what repeated irreversible memory permits under explicit timing and access rules. It does not by itself show that a particular context-management system improves an agent. Generic rate–distortion, coding, dependency graphs and feedback methods are established prior work.

03 / Decisions

How the direction evolved.

Each turn in the project follows a finding or a limitation. Negative results are part of the story.

Sep 16–18

Make the forgetting problem precise.

Focus on dependencies revealed after compression. Separate irreversible memory from retrieval and declare every information channel.

Why this mattered

A system that can reread an archive has a different problem from one that has genuinely discarded the source. The formal contract makes those differences testable. Protocol ↗

Sep 19

Test retention separately from eventual success.

Reliable recovery can hide poor memory. Measure what is available before recovery and the cost of finishing. The large matched selection study did not establish a guidance benefit.

Decision & evidence

The exact four-bit computation settled the local chain optimum at 9/32. Model selection results stayed separate: 1,536 dispatches, three permanent losses, and a primary benefit interval including zero. Study ↗ · Pilot specification ↗

Sep 21

Check joint encoding before generalizing.

Encoding blocks together beats simply repeating the one-block solution. Extend the proof to all decoders instead of multiplying the small example’s gap.

Decision & evidence

The two-block witness and decoder-complete frontier narrowed the asymptotic answer. They are coding results, not natural-language results. Joint coding ↗

Sep 21–22

Check proposed memory before throwing evidence away.

Collision audits and cumulative failure constraints repair constructed cases. A strong critical-field baseline matches the feedback loop, so generic repair is not the contribution.

Decision & evidence

Cumulative repair moves the finite fixture from 32/48 to 48/48 successful executions; static retention also reaches 48/48. The novelty audit narrows what can be claimed. Feedback result ↗ · Novelty audit ↗

Sep 22

Keep direct records and indexed recovery as serious rivals.

They are cheaper or more reliable across several inspected studies. A narrow schema-transfer win does not establish broader superiority.

Decision & evidence

The different-schema test meets its narrow comparison against prompting, while indexed recovery is cheaper and succeeds on all eighteen cases. Cross-record stress later exposes additional failures. Schema study ↗ · Stress test ↗

Sep 29–Oct 1

Move toward executed work, then audit the evidence.

Actual command receipts make claims more concrete. But one intake task is not a natural-workflow evaluation, and a final model can misuse evidence it still has.

Decision & evidence

The retained-evidence audit reuses 319 final answers; it is not 319 new calls. Strong static/common-codec controls reach 24/24 scope queries. The inspected intake task needs only its later checkpoint for the actual question. Evidence audit ↗ · Static control ↗ · Timing audit ↗

Oct 2

Close a substantial theory checkpoint.

Complete the asymptotic curve and finite construction sequence. Price the public tables and local runtime alongside the error improvements.

Decision & evidence

C75 and living draft v0.42 mark the scientific checkpoint. The saved closeout records 597 passing offline tests and a paper build with 48 cited sources; later development work does not silently upgrade the manuscript. Closeout ↗

Oct 7–8

Isolate rollback after a naturally rejected attempt.

Keep the checkpoint, public feedback and lesson fixed while removing the failed trial. Earlier engineering tasks yield too few recovery pairs; a math follow-up gives an uncertain +1.85 pp difference.

Decision & evidence

The 32-task mathematical cohort was chosen after observing earlier engineering results, so it is development evidence. It produced 27 recovery pairs, not proof of a mechanism or a confirmatory win. Design ↗ · v4 result ↗

Oct 8–9

Test whole policies and repeated cuts; preserve unknowns.

A user-authorized amendment lets independent jobs finish when another trajectory has an unknown response. Completed v5 shows zero mean quality differences and strong control ceilings.

Decision & evidence

Original evidence remains sealed. Unknown responses stay missing; none is retried or scored as a failure. The same 48 tasks appear in three tracks, so their pairs cannot be added as independent tasks. Amendment ↗ · Completed v5 ↗

Oct 9

Calibrate difficulty without selecting for a rollback win.

Use K/F controls first. v6 makes the tasks harder but yields no eligible recovery cell. Prepare a new screen that requires a best candidate at every action.

Decision & next gate

Do not remove the checker-mismatch gate after seeing results. The separate six-task follow-up needs its own allocation of at most 84 generations; no live calls have been made. Frozen follow-up ↗

Strong controls stay in.

Direct retention, recovery, cached outcomes and fresh solving can win. Preserve easy cases and negative results.

Missing stays missing.

Interrupted calls and unstarted tasks are visible. Never convert them into successful or failed answers.

Evidence keeps its scope.

Local proof, offline replay, model observation and unperformed plan remain distinct.

A short glossary
Parent / child memory
The representation before / after a later compression. In the bit model, the final decoder cannot access the discarded parent.
Public side information
Shared rules or cues that a decoder is explicitly allowed to see. Their timing changes the problem.
Direct retention / indexed recovery
Keep the relevant records immediately / retrieve records through a declared index when needed.
Public mismatch
A checker rejects an actually submitted candidate. Deferring an answer until the action budget runs out is a different failure.
Rollback
Remove the visible raw trial while keeping the accepted checkpoint, feedback and lesson. It is not a claim to edit the provider’s private reasoning.
F: Fresh solve
In current v5/v6, each action starts from the original artifact and all released public evidence, without trial history or lessons.
Complete pair / unknown
Both compared outcomes are observed / a dispatched response or outcome remains unresolved. Unknowns are not zeros.
pp / descriptive interval
Percentage points / uncertainty summarized for the observed task cohort. It does not establish generalization to new task families.
Planning credits
A declared resource-accounting unit. They are not measured subscription charges or API dollars.
Native compaction
The provider or deployed harness’s own context-management path. Our controlled visible-memory studies do not establish superiority over it.
