# Feedback-loop research: next-stage design

September 22, 2026. **Offline design, not a live model-launch contract.**
The completed [finite adapter](../research/FEEDBACK_BEFORE_FORGETTING_2026-09-22.md)
provides failure controls. No new model allocation has been used or established
by this document; all previous completed study artifacts remain unchanged.

## Decision to test

Can specific, independently validated failure feedback improve downstream task
completion beyond extra revision compute and strong critical-field retention,
when two successive memory limits bind and all information/cost channels count?

The existing adapter cannot answer that behavioral question: schema candidates
are hand-written, worlds are enumerated, and the public rule gives the strong
baseline the exact solution. Do not launch a larger copy of that easy family
and call its repetitions natural-task evidence.

The [strict novelty audit](../research/FEEDBACK_NOVELTY_AUDIT_2026-09-22.md)
also removes a general algorithmic novelty claim: finite recovery/repair is an
accepted-strategy and weak-coloring problem. Before a new launch, demonstrate
extraction of replayable delayed-failure evidence from executable snapshots,
state which coverage remains unknown, and measure reuse/invalidation of old
checks across revisions. These are candidate engineering capabilities; their
mere combination does not establish priority over existing verification systems.

## Required task material before a launch

Prepare pinned local workflow snapshots with versioned artifacts, completed
checks, negative results, and later obligations that have executable acceptance
tests. Public rules must make some source facts irrelevant while others remain
necessary. Every arm receives the same original evidence, tool permissions,
artifact visibility, memory limits and public future-task distribution.

Payloads must be opaque values outside a tiny preenumerated catalog. Exact bytes,
names, ordering, filenames, selected schema IDs and retained metadata are part
of memory. If fixed program code contains instance values, count it as an archive.
Neither evaluator files nor raw transcripts are available after deletion.
Declare provider-side history, opaque state and retained KV representations;
an API boundary alone does not prove they were erased.

Separate development snapshots from evaluation snapshots by obligation structure
and artifact values. Have the environment generate only authorized observations.
Freeze terminal graders and independently inspect their coverage before optimizing
the compactor. Feasible, insufficient-capacity, cheap-recovery, late-target and
harmless-forgetting conditions are all necessary controls.

## Comparison arms

| Arm | Intervention | Purpose |
|---|---|---|
| Structured one-pass | Initial proposal under the same final memory cap | Initial behavior and cost reference |
| Revision without specific diagnosis | Same maximum revision rounds; generic preservation advice | Extra computation control |
| Last-only diagnosis | Most recent independently validated failure | Test regression/cycling risk |
| Accumulated diagnosis | Recheck all prior obligations on each revision | Candidate feedback mechanism |
| Critical-field retention | Equally informed schema or rule extractor, under identical cap | Strong simple baseline |

Add oracle/certified bounds only as explicitly privileged diagnostic references.
A correct-field list extracted from evaluator truth is not a deployable baseline.
Similarly, the repair mechanism cannot see actual held-out targets before the
boundary unless all arms receive the same early-target treatment.

For the finite artifact, exhaustive enumeration is a useful compute control.
For a stochastic model, generic extra revision is still unperformed. The current
`enumerate` arm must never be relabeled as a generic-feedback LLM result.

## Feedback contract

Specify separately what each component observes:

- Proposer: source history while it is available, current candidate, public
  contract and the permitted feedback packet.
- Verifier: restored evaluation state and a bounded set of declared tests or a
  sound certificate procedure. Full truth access belongs here, not in executor
  prompts or hidden files.
- Executor after compaction: actual retained bytes, declared public observations,
  and costed allowed tools only.

A feedback packet identifies the failed obligation, revision/access scope and
the constraint being checked. Count its bytes and all model calls used to form
it. Distinguish packet formats that reveal source values from formats that merely
point to fields. Both can help before deletion; after deletion a revealed value
is a retrieval channel. Oracle correctness labels, repeated terminal attempts,
test IDs and success/failure responses can also carry instance information.

Source history remains available until a candidate is accepted or a fixed repair
budget is exhausted. Define acceptance, fallback, and infeasibility outcomes
before running. A failed robust certificate is not evidence of likely average
failure. A passing sampled test set is not a robust certificate. If verification
is incomplete, return unknown coverage instead of calling a memory safe.

## Analysis and cost

Freeze a maximum repair count and a total per-episode resource allowance. Report
success-versus-resource curves because one-pass and iterative methods naturally
use different compute; do not silently credit unused compute as a gain. Include
verification, repair, retrieval, cache changes, retries, rework, failures and
latency. Keep record slots, bytes, tokens, state bits and provider charges separate.

Primary comparison: accumulated diagnosis versus the strong critical-field arm
at matched total resource limits, using complete runs and paired initial states.
Secondary: targeted versus generic revision and accumulated versus last-only.
Report pre-recovery availability, terminal success, repaired-then-regressed
obligations, unresolved/unknown verdicts, and actual full costs. Recheck after
the second boundary and continue through delayed terminal obligations.

Pair environment and context restoration in diagnostic continuations. Complete
runs are also required because memory can change actions and future observations.
Freeze the repair policy on development data; evaluation failures do not trigger
policy or task-template tuning. Keep invalid responses, missing outcomes and
transport costs. Select a sample size using a stated effect size and variability
estimate, not by treating finite world combinations as independent subjects.

## Launch fields still unfilled

Model/provider revision and settings, transport/isolation evidence, task snapshot
hashes, private evaluation split, seeds, exact prompts, independent grader review,
repair cap, sample size, request ceiling and spend cap all remain unfilled.
Completing the local artifact does not silently fill any of these fields.

## Stop or change direction

Downgrade a superiority claim when critical-field retention matches the loop at
equal resources; that is already the outcome in the finite fixture. Stop if
feedback depends on inaccessible evaluator facts, world enumeration is essential
at realistic scale, or apparent success comes from an uncounted channel. A useful
audit/refusal tool could still be an engineering result, but must be evaluated
on its own utility rather than marketed as a better compressor.
