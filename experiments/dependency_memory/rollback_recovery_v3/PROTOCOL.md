# Harder-task rollback development study v3

October 8, 2026. Prepared after the earlier authored pilot produced one paired
math task and no coding pairs. The user asks to keep going to find useful results,
retains GPT-6 Luna through their Codex subscription and has removed token/cost
budget ceilings. This is a new development study, not confirmation or an attempt
to continue a closed launch. Outcomes are unperformed until the frozen manifest's
new generation identities are dispatched.

Freeze all 64 new tasks before the first model outcome: 32 constructed math
problems (8 integer, 8 modular, 16 list-coloring) and 32 original Python coding
problems (eight algorithmic families, four variants each). No earlier task,
calibration fixture or outcome supplies a study answer. Statements explicitly
require scalar colors/integers for math and Python 3.11 standard-library programs
for coding. Public examples include edge cases selected by the generator before
model outputs; reserved tests and references never reach the actor. Validate all
references in digest-pinned isolated Docker and math with the independently
enumerated formulation before freezing.

Checkpoint and initial branch calls use **low effort**. Both writers and every
terminal continuation use **medium effort**. This tests deletion after a cheap
initial attempt; it is a changed actor policy, not a result for the old all-medium
setup. Verify both efforts in the signed-in model catalog and actual installed
client requests to an unauthenticated localhost mock before dispatch. A fresh
process, empty ephemeral workspace, no replayed reasoning/history and the existing
fixed global instructions/tool-wrapper audit apply to every request. Reject every
tool attempt, model fallback, missing usage and potentially repeated identity.

Retain the original episode rule: one checkpoint, up to two initial branch steps,
one lesson and one generic summary after a well-formed public mismatch, then two
independent terminal draws per scheduled arm. Public pass ends the initial
episode, even when reserved grading fails. No candidate, syntax/runtime error,
malformed record or writer failure is preserved rather than repaired/retried.
Never manufacture a wrong branch or replace tasks to increase eligibility.

K=C+B+F+L, R=C+F+L, Z=C+F, G=C+F+S. K/R instructions and C/F/L bytes must match;
only B differs. K and R both fit before either is dispatched. A failed lesson
blocks K/R only; failed summary blocks G only. Grade all terminal draws after
all scheduled generations for that task. Objective success is exact constraint
satisfaction or passing the frozen retained coding suite, not universal program
correctness. Optional human ratings remain unknown without the original masked,
independent-review rubric.

The complete-client-body admission bound increases to 131,072 UTF-8 bytes.
The common writer acceptance bound is 4,096 visible UTF-8 bytes including JSON,
and this bound is explicitly stated in each writer request. Neither bound is a
provider tokenizer count or an output-token cap. Provider-default output and the
conditional published 1,050,000-input / 128,000-output envelope remain declared.
Calculated subscription credits are separate from unavailable account charges;
reasoning is a subset of output. No credit purchase, fallback or API-key billing.

Eight separate live format/transport calibration calls use the existing fixtures
and are excluded from every study outcome. Freeze their exact requests and
identities too; an invalid format or unknown dispatch stops the whole study.
The total possible allocation is 840 calls, including calibration.

All 832 possible study call identities (64 x 13) are frozen. Four sequential blocks
of 16 tasks have separate at-most-208-call ledgers, within the tested ledger's
existing 320-call capacity. Blocks are an accounting partition, not an adaptive
sampling policy. Every block and task belongs to one fixed cohort. Unknown
dispatch/usage stops the entire study and leaves all remaining slots unperformed;
never launch a later block to evade an unresolved reservation. An exclusive
study marker prevents relaunch. No cost ceiling or significance stopping rule.
The response observation deadline is 900 seconds per dispatched call; expiry is
unknown dispatch, never a zero score or authorization to retry.

Primary outcome: task-level R-minus-K conditional recovery, separately for math
and coding, with every selected task's initial disposition, preparation failure,
capacity loss and missingness retained. Fewer than six complete paired tasks in
a domain remains a feasibility failure. Six is not a power threshold. Report
individual pairs, conditional arm totals, fixed-denominator missingness bounds,
exact rejected-candidate repetition, input/output/cache usage, elapsed time and
costs. Use the frozen order's first example in each outcome class.

Coding variants share eight algorithmic templates. Report family counts and
family means; use a family-resampling descriptive interval only with at least
six represented eligible families. Do not treat variants or terminal draws as
independent families. Task-level intervals, if shown, are separately labeled
conditional on this constructed task set. Math uses three constructed strata;
give stratum results and do not claim inference to new mathematical templates.
No confirmatory p-value or manuscript upgrade follows automatically.

Complete all 64 tasks regardless of observed effect direction. If this cohort
still lacks opportunities or has a recovery floor/ceiling, report that result
and choose any next development design separately. Do not silently keep sampling
until rollback wins. The original LiveCodeBench proposal and later full-policy,
autonomous and native-harness comparisons remain separate, unperformed designs.

Current official model documentation supports low and medium efforts; actual
subscription availability is checked locally. The alias is mutable and no
immutable server revision or provider sampling seed is available. Reference:
[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Codex app-server](https://learn.chatgpt.com/docs/app-server).
