# Continuation after one permanent transport failure

September 22, 2026. The original [cross-record protocol](../cross_record/FROZEN_PROTOCOL.md)
explicitly prohibited resumption. Its run stopped after 199 dispatches:
198 completed and the next CI projected-index final call failed in the
provider transport, without usage or an answer. This continuation is a
**separate post-stop extension**, not a completion of that original
preregistered study. It may produce a descriptive 35-complete-pair comparison;
the original 36-pair primary success criterion remains unestablished.

Before any new model call, freeze the ordered 348-identity schedule from the
original runner, the exact 199-identity attempted prefix, hashes of every
original call/episode/manifest/completion file, the identity of the one failed
call, and the remaining ordered **149 never-dispatched identities**. Do not
read or tune to original model answers when choosing this continuation. The
failed identity is never retried. Preserve every original response and cost.
For a partially completed trace, use its already saved parent/child memory and
index; do not regenerate them. New traces use the same frozen original
generator, prompts, caps, graders, arm order and methods. Every new model call
gets a fresh isolated thread. The continuation has a new output directory and
a **149-dispatch / 25-planning-credit** ceiling, in addition to the original
allocation. No API key, purchase, reset, model switch or retry.

If a new call has the same explicit provider-generation error after a durable
dispatch reservation, mark it permanently missing and advance to the next
identity using a fresh adapter. Count it as a terminal failure if it is a final
decision. Preserve its 7.65-credit uncertainty reservation against the new
25-credit cap. Stop on any other transport/accounting/isolation uncertainty.
Malformed but fully metered answers count in their original denominator.
Do not condition the schedule on any answer or failure outcome.

Analyze all 348 scheduled identities with a status ledger and separate
failure provenance. For a fully measured paired comparison, exclude any
future with a missing response in any arm, rather than filling it with an
inferred answer. Report exact failure counts on that complete-pair subset,
plus all attempts and missing calls. Whole-schedule cost for an arm with
unknown usage is an interval; do not present a precise measured total for it.
Local bytes and CPU lost between the original failed recovery and its aborted
episode write are also unknown. The original primary criterion cannot be
rescored as if this continuation had been prespecified. Even on complete
pairs, treat evidence as constructed and exploratory.
