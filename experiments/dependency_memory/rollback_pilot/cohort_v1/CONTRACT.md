# Authored 24-task subscription engineering pilot, version 1

October 8, 2026. This is a disclosed amendment to the proposed E2, frozen before
any task answer. It exercises the four-condition experiment implementation with
the user's existing Codex subscription, GPT-6 Luna medium, and no token or cost
budget ceiling. The original LiveCodeBench v0.2 comparison remains unperformed:
its source permissions and complete reference-program package are unresolved.

The cohort contains the specified 12 generated math tasks and 12 original
repository-authored coding tasks. Coding has four tasks in each authored
structural stratum (easy, medium, hard); these are not benchmark difficulty
ratings. Each coding task has two public examples and eleven reserved tests,
including an analytic stress case. Independent finite oracles and original
reference programs are checked in the pinned Docker runtime before launch.
Success means passing this retained suite, not proving a program correct for
all inputs. No task is replaced after an answer, and no failed branch is forced.

The original checkpoint, branch, public-feedback, lesson and generic-summary
formats, fixed task ordering, alternating writer ordering, balanced terminal
ordering and two draws per condition are retained. K is C+B+F+L, R is C+F+L,
Z is C+F and G is C+F+S. Both K and R must fit admission before either is
scheduled; C/F/L are identical. Public pass ends the initial episode. Only a
well-formed candidate with a public mismatch is a recovery opportunity.
Malformed records do not get a format retry. Reserved-test failures never enter
actor feedback. All terminal generations precede their grading within a task.

This allocation permits at most 312 generation attempts for the 24 tasks,
separate from the completed eight-call E1 allocation. There is no credit ceiling.
The E1 subscription access, retry, isolation and accounting amendment continues
to apply: a fresh official app-server process and ephemeral empty workspace for
every request, no replayed reasoning or provider conversation, no enabled data
tools, no automatic retry, unknown dispatch/usage stops the allocation, and no
purchase or credit fallback. Fixed global instructions and allowlisted client
tool wrappers are disclosed; any attempted tool use stops the allocation.

Admission is a complete-client-body UTF-8 byte bound of 32,768, not a provider
tokenizer count. Writers have a 1,024-visible-byte cap. No configurable 16,384
output-token cap is established for this CLI. Provider-default output is used;
1,050,000 input / 128,000 output tokens are a conditional published model
envelope, not a proven server-side cap. The per-call 4.225-credit reservation is
a conservative conditional planning amount. Actual telemetry and calculated
planning credits are reported separately from actual account charges. No API
key is used and API-dollar estimates do not price this run.

The installed CLI hash, global instruction hash, configuration, current model
catalog, runtime image, exact task material, source files and 312 possible call
identities are bound before launch. Provider sampling seeds and immutable server
model revision are unavailable. The frozen local seeds select tasks and order;
they are not provider sampling seeds. An exclusive launch marker prevents
relaunch, including after interruption. Every selected task and unperformed slot
is retained. Analysis is task-level and separate by domain; fewer than six
eligible paired tasks fails the proposed feasibility screen. No general rollback
benefit, novelty claim, manuscript upgrade or later-stage allocation follows
automatically from this engineering pilot.
