# Workflow method audit and prospective runtime

October 1, 2026. The [design](PROTOCOL.md) was committed at `66cebac` before
implementation. Historical outcomes and E0001 were already known. This is
offline research, not a live launch or new prospective result.

The [research note](../../../research/WORKFLOW_METHOD_AUDIT_2026-10-01.md)
states the deduction and its limits. The
[reproducible report](../results/workflow_method_2026-10-01/report.md) checks:

- 158,340 queries against a separate reverse-scan grader specification;
- 158,340 direct-projection query outcomes;
- 5,652 original checked-writer proposals;
- 52,780 two-boundary checked/direct state comparisons.

All agree. These are finite constructed checks, not task or model trials.
External human review is pending. Known receipt roles are supplied, not inferred.

In this exact-table format, the old checked writer and fallback retain the same
receipt state as direct projection. Old JSON presentations can differ and change
model behavior. The new canonical shadow has the same bytes as direct memory;
it is an offline diagnostic rather than an extra paid arm. Future primary arms
are direct, indexed recovery, prose and full history, with two prose writers and
four final slots. Every final receives the same retained-evidence check.

The actual E0001 query is answerable from B alone. Direct children also fit.
That episode tests interfaces and final use, without requiring its parent
memory. The intake screen preserves such easy tasks and reports actual parent
dependence before any model study. It does not create harder query variants and
call them additional natural tasks.

With exact-snapshot reporting, A receipts for other trees are irrelevant even
if B leaves a check missing. Selective command capture alone does not change
that restriction. Any different reporting contract needs another method version.

The new logical request cap is 262,144 bytes. E0001's full-history request is
163,432 bytes. The design's phrase “100,000-byte transport envelope” refers to
the old **logical public-request** cap in `workflow_eval_live/protocol.py`;
actual provider wire size is a separate, unverified launch field. Neither cap
changes the 4,096/1,536 UTF-8 memory limits. No logs are clipped.

The method lock covers implementation, tests, protocol and source dependencies.
It excludes future task data, evolving notes and generated reports. Do not
overwrite it; a method change needs another version. The CLI refuses existing
outputs and writes only into ignored `build/`. Fixture completions are scripted
interface controls, including JSON for the prose slot; they are not model/prose
performance. Saved-response replay verifies each identity and request hash.
There is no built-in live transport.

The pure interfaces exclude evaluator metadata from serialized requests. They
are not process sandboxes. Indexed/full access is explicit; archive construction,
retention duration, retrieval bytes and local CPU/elapsed time are recorded as
unpriced resource vectors. The runtime stops on a missing response or oversized
public request, preserving the prefix and later undispatched identities. It
never retries or replaces an answer with the deterministic diagnostic readout.

Future consecutive whole tasks remain in the
[single-repository intake](../workflow_intake/README.md). A selective actual-command
collector/registration format for variable future checkpoint sequences, twelve
prospective episodes, external grader review, a provider audit and a bounded
allocation remain launch gates. The existing three-command development collector
is not a prescription to refresh every check at every future B boundary.

Validation: 448 offline tests pass, the repository validator reports PASS, and
the paper builds with 39 cited sources. The fixture CLI completes six scripted
slots. New provider generations and prospective evaluation episodes remain zero.
