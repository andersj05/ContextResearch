# Cross-record recovery and check comparison (prospective third study)

September 22, 2026. Freeze this protocol and the four development fixtures
before implementation is committed or evaluation seeds are derived. This is a
new constructed stress test of the previously observed recovery advantage, not
independent field data or an unseen-schema transfer. It adapts the same public
workflow grammars, but each related object now arrives from a separate tool
with a shared opaque `workflow_key`; result order is shuffled. Do not use the
two earlier studies' evaluation answers to change the method or caps here.

## Split, timing, and fixed sample

Development: escrow and package, seeds 61011 and 61012. Evaluation: retry
queue, CI promotion, data pipeline, four seeds each. Evaluation seeds are the
first 32 bits of SHA-256 of
`cross-record-v1:<implementation-commit>:<family>:<repetition>` for repetitions
0–3, where `implementation-commit` is the complete code-freeze commit hash.
Freeze all twelve fixtures and hashes before any evaluation model call. The
original generator and terminal rules are pinned in the earlier study; each
new fixture has seven workflow roots and one component result per schema
object. The exact terminal decision is checked on three prespecified futures
per trace: irrelevant note on an invalid candidate, a repair on that candidate,
and a gate-changing event on a valid candidate. That gives 36 paired cases.

Only public tool schemas, public tool results and the decision rule are shown
at the first boundary. At most **7,000 UTF-8 bytes** of parent memory survive.
Two candidate IDs are then shown; at most **2,600 bytes** of child memory
survive. Only then does the target and late event arrive. Model calls use fresh
threads/processes and cannot see previous provider history, opaque reasoning,
fixture files, evaluator truth, or archive unless the method explicitly gets
indexed recovery or full history. Proposals are admitted once, truncating at
the byte cap with no reprompt. A deterministic projection that exceeds a cap is
infeasible; never silently clip it. Public requests have a 16,000-byte bound.

## Fixed arms and certificates

1. **Prompt:** a data-first, strong prose memory writer at both boundaries.
2. **Structured:** a separate writer asked to use a compact field/row table,
   with no validation or repair. This tests simple serialization.
3. **Checked:** share and fully charge the structured parent proposal. Apply
   generic exact-ID and relationship checks; on a failed check use the generic
   projection. A separate child writer sees that bounded parent, with the same
   check and fallback at the child boundary.
4. **Automatic:** generic projection and the same checks without model writers.
5. **Direct:** hand-written per-family field selections at both boundaries.
   Human design time is unmeasured.
6. **Indexed raw:** build an index over all original results; after target
   disclosure retrieve the root and **every** component joined by the exact
   workflow key. Do not give only the root.
7. **Indexed projected:** build the same index, retrieve the entire joined
   workflow, then run the generic projection over that workflow. This is the
   strongest compact recovery control.
8. **Full:** read all original public results again at execution.

The generic logic may inspect only standard schema/result content, including
types, patterns, enums, field names and values. It must have no evaluation
family names or hard-coded critical paths. Check one requires exact bytes and
multiplicity for every detected identifier. Check two requires the original
workflow, component and field-path association for each identifier/reference.
An untyped short string with uncertain coverage returns unknown, counted as a
failed certificate. State semantics are outside the certificate; record that
limit. Join completeness, ambiguity and failures are counted, never inferred.

The **primary success criterion** is fewer exact terminal failures for
automatic than both prompted arms at equal or lower *total* experimental cost,
no more failures than hand-written direct, and a nondominated cost/failure
point relative to indexed projected. Report all arms, per-family and per-event
failures, certificate verdicts, raw/admitted lengths, information sufficiency,
and the cost frontier regardless of the outcome. Treat a tie with indexed
projected as support only if automatic costs less. No tuning of implementation,
prompts, caps, method order, grader, or price weights after the implementation
freeze.

## Cost and launch limit

The exact schedule is **348 model calls**: five writer calls on each of twelve
traces (prompt parent/child, structured parent/child, checked child) plus eight
fresh final calls for each of 36 futures. Shared proposals are charged in full
to each hypothetical method. Count every dispatched call, including malformed
outputs, with cached and uncached input, output and reasoning tokens. Count
local extraction, checking, joining, selection, index construction/storage,
archive reads, projection and memory copies. Record wall time. Synthetic local
conversion: 0.0001 planning credit per CPU second plus 0.00000001 credit per
byte locally read **or written**. These are explicitly constructed weights,
not observed provider billing. Report token-derived model planning credits,
local charges, and cache-neutral sensitivity separately. Actual debit and
human authoring are unknown.

Use the audited managed-subscription fresh-thread `gpt-6-luna` medium transport
and pinned local profile. A new client instance may be opened after at most 120
completed calls to respect the adapter's per-instance 144-call cap; the study
has a single global ledger, unique identities and **356-dispatch / 50-planning-
credit** ceiling. No retries, resume, model fallback, API key, purchase, reset,
or schedule expansion. Save immutable public requests, answers, usage, source
hashes and terminal completion state. Any uncertainty stops the run.

This tests whether generic checks/projection can pay for themselves when
dependencies span results. A single constructed distribution, reused domain
grammars, synthetic local prices, and inaccessible provider internals limit
generalization. External held-out trace replay remains future work.
