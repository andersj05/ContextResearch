# A stronger zero-model scope control with the codec held fixed

October 1, 2026. **Post-hoc offline inspected/constructed development.** Claim
C64. Three repository programs and a constructed late-key family are not
independent natural workflows. No new model call, universal semantic guarantee,
minimal-scope certificate, slicing novelty or production benefit is claimed.

The [new source-analysis control](../experiments/dependency_memory/scope_static/README.md)
recovers a finite-catalog-complete dispatch contract without seeing record values,
the authored contract, evaluator labels or the seven saved model responses.
Its inferred contract and the authored contract both answer **24/24** delayed
record queries with a 1,958-byte parent and 950–1,009-byte children under the
unchanged 4,096/1,536 caps. A uniform-codec replay of the seven model contracts
also gives 24/24 for five and 0/24 for the two oversized contracts. No observed
model contract beats this zero-model control in this inspected workload.

This removes the weak whole-subtree AST baseline as a reason to continue model
calls on the same classifier. It does not establish a general extractor, an
independent prompt ranking or fully priced lifecycle superiority. The
[original eight-dispatch study](SCOPE_INFERENCE_FINDINGS_2026-10-01.md) stays
closed with its permanent missing answer and unassessable primary comparison.

## 1. Analysis input and inferred contracts

The analyzer receives public source, the entry name and formal record-parameter
name. It parses ASTs without running their code. Evaluator catalogs, observations,
authored projections and model outputs are not parameters or dependencies of
the analyzer module. The evaluator separately compiles selected trusted pure
repository functions in explicit namespaces. This is a trusted-function offline
information contract, not isolation for untrusted code or a native agent.

The heuristic propagates dictionary aliases, constant keys and finite literal
helper arguments. It distinguishes full values, key membership and container
type/truth uses. Branch aliases are joined conservatively. Dynamic keys retain
their entire base; unsupported data iteration, mutation, recursion or reflection
retains the entire input. The original projection DSL preserves encountered
nondictionary values, rather than silently converting their types. Presence
cannot override a simultaneous truth requirement with a `true` placeholder:
that would change an empty dictionary into a truthy value.

There are 51,551 distinct family-labelled input/query pairs; the dispatch catalog
preserves its fifteen repeated rows. Errors and malformed inputs remain in the
denominator. Token/quota original exceptions are compared by class and message;
dispatch uses its historical explicit unknown outcome. Matching finite output
digests do not prove correctness for all Python inputs or programs. Quota's
agreement follows from retaining its whole input and is not a successful
narrowing result. The token validator's historical constants describe that
pinned program, not today's prices, debit or provider rules.

The late-key case retains every potentially requested map entry, including keys
outside the evaluator catalog. Caching the outputs for all present keys and the
missing-key default would provide equivalent information. This does not prove
an information-theoretic disadvantage of caching or a new dynamic-query method.

## 2. One codec, fixed memory limits and explicit public schemas

All projected arms use the unchanged `evidence.encode_fields/decode_fields`
algorithm with a schema derived only from their public contract. Leaf values
remain literal. Schemas are fixed before instance encoding; they do not contain
record values. Array-order differences in contracts do not change the canonical
schema. The schema is public side information rather than instance memory;
its serialized bytes and hash are recorded separately. The static schema is
263 bytes and the authored schema is 240 bytes. This convention is not a claim
about total executable/model-request storage.

The one-byte difference from the earlier C58 1,957-byte parent is the separately
canonicalized schema/marker serialization. Earlier sources and results are
unchanged. This table holds the codec algorithm and caps fixed across these
arms; it is not an improvement in the codec or the historical model's behavior.

The source disappears after parent transformation. The child can select only
admitted parent rows for its announced worker pair; final decoding can read
only admitted child memory and the exact case/request identity. Infeasible
memory becomes empty without clipping or source resurrection. All six worker
pairs and twenty-four eligible final queries are checked. Tests reject absent,
wrong-identity and ambiguous duplicate evidence. Public source/schema access is
declared; archives, opaque reasoning and provider sessions are absent.

## 3. Post-hoc replay of the already observed model contracts

Read the two immutable C61 analysis files and replay only their seven admitted
contracts under the common codec. This is scripted offline replay, not new LLM
final decisions, an independent replication or a replacement for the missing
eighth answer. The original study and its original plain-JSON scores remain
unchanged.

Four of the five fitting model contracts use the 1,958-byte parent and
950–1,009-byte children. The fifth uses 2,329 parent bytes and 1,109–1,221 child
bytes. All five answer 24/24. The two whole-accounting contracts still propose
14,758 parent bytes, exceed 4,096 and answer 0/24. Each remains complete on the
unchanged finite dispatch catalog, showing that semantic sufficiency and byte
feasibility are separate. Cached known-program outcomes remain the smaller
successful control.

No new generation cost is incurred. The old known 0.2232910 planning credits
and permanent 7.65 unknown reservation stay in C61; this replay does not release
the reservation or alter debit evidence. Local extraction/evaluation CPU and
elapsed nanoseconds and read/write byte counts are reported but unpriced.
Therefore no fully priced production-cost advantage follows.

## 4. Primary-source comparison and limits

Horwitz, Reps and Binkley, *Interprocedural Slicing Using Dependence Graphs*,
ACM TOPLAS 12(1), 26–60, January 1990, DOI
[10.1145/77606.77608](https://doi.org/10.1145/77606.77608), is an established
precedent for tracking dependencies through calls. Its original abstract and
opening Introduction, pp. 26–27, were read through the
[primary-text preview](https://paperity.org/p/376573037/interprocedural-slicing-using-dependence-graphs)
on October 1; the [author project page](https://research.cs.wisc.edu/wpis/html/)
corroborates the byline, venue and DOI. The preview's separate catalog byline
contains an extra name; the original article's three-author byline governs here.
The publisher PDF was blocked, and the author-hosted PostScript was unsupported
by the reader. The rest of the algorithm/proofs and replication were not read.
The attempted scanned Weiser paper was not successfully read and is not added
as a reviewed source.

The reviewed introduction identifies data and control dependencies and the need
to preserve call context. Our inference is that automatic dependency extraction
and helper-sensitive analysis are strong required baselines, not novelty by
themselves. The new heuristic does not implement or improve that paper's full
algorithm. Eleven tests use independently executed generated programs, malformed
alias types, branch joins, presence/truth overlap, unused-key exceptions, late
keys, conservative fallbacks, codec roundtrips and irreversible-memory checks.
Randomly renamed generated programs use development seed 2026100103, not held-out
natural tasks or a model sampling seed.

The next empirical study should use a separately frozen new program/workflow
cohort, include these controls, and retain easy and unsupported cases. A broad
claim needs richer structures, actual variable-command intake, independent
evaluation and all extraction/recovery/failure costs. More generations on the
same inspected classifier would not answer those questions.
